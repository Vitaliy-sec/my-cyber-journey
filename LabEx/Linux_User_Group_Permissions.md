### 1. Управление пользователями и группами

**Что делал:**
- Просматривал информацию о текущем пользователе и системе
- Создавал новых пользователей с домашними директориями
- Назначал пользователям дополнительные группы
- Понимал принцип User Private Group (UPG)

**Какие команды использовал:**
```bash
# Просмотр информации о пользователе
id username
whoami

# Создание нового пользователя
sudo useradd -m devops
sudo passwd devops

# Добавление пользователя в группу (например, docker, sudo)
sudo usermod -aG docker devops

# Просмотр всех групп пользователя
groups devops

# Просмотр файлов с информацией о системе
cat /etc/passwd | grep username
cat /etc/group | grep docker
Что понял:

При создании пользователя автоматически создаётся группа с тем же именем — это его первичная группа

Вторичные группы нужно добавлять вручную через usermod -aG

Без -a (append) можно случайно удалить пользователя из других групп

2. Выдача прав sudo
Что делал:

Добавлял пользователя в группу sudo, чтобы он мог выполнять команды с правами администратора

bash
sudo usermod -aG sudo devops
Как проверил:

bash
# Переключился на пользователя
su - devops

# Проверил, есть ли права sudo
sudo -l
3. Управление правами доступа к файлам
Что делал:

Изучал вывод ls -l и расшифровывал строку прав (rwxr-xr--)

Менял владельца и группу файла

Изменял права доступа числовым и символьным методами

Пример файла до изменений:

bash
-rw-r--r-- 1 user user 1024 script.sh
Изменение владельца и группы:

bash
sudo chown devops:www-data script.sh
Изменение прав:

bash
# Символьный метод: владелец (rwx), группа (r-x), другие (---)
chmod u=rwx,g=rx,o= script.sh

# Числовой метод: rwx = 7, r-x = 5, --- = 0
chmod 750 script.sh
Что означают цифры:

Цифра	Права	Бинарно
7	rwx	111
6	rw-	110
5	r-x	101
4	r--	100
0	---	000
4. Понимание специальных битов (SUID, SGID, Sticky Bit)
Что делал:

Искал файлы с битом SUID (например, /usr/bin/passwd)

Понимал, зачем они нужны

bash
# Поиск файлов с SUID
find / -perm -4000 2>/dev/null

# Пример: passwd должен запускаться от root, чтобы менять файл /etc/shadow
ls -l /usr/bin/passwd
# Вывод: -rwsr-xr-x 1 root root ...
Что понял:

SUID (4000) — файл запускается от имени владельца, а не того, кто его запустил

SGID (2000) — файл запускается от имени группы владельца

Sticky Bit (1000) — на папке: только владелец может удалять свои файлы (например, /tmp)
