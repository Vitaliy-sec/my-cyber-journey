# TryHackMe: Data Encoding

## 📌 Краткое описание
Пройден модуль, посвящённый способам кодирования текстовых данных в компьютерных системах. Изучены стандарты ASCII и Unicode, а также кодировки UTF-8, UTF-16 и UTF-32. Понимание этих концепций критично для анализа данных, работы с логами, предотвращения веб-уязвимостей и обработки текстовой информации в различных системах.

## 🛠️ Ключевые навыки, полученные в модуле

### 1. ASCII (American Standard Code for Information Interchange)
- **Что это:** 7-битный стандарт для представления английского алфавита, цифр и управляющих символов.
- **Ограничения:** Поддерживает только 128 символов → не подходит для других языков, специальных символов и эмодзи.

### 2. Unicode
- **Что это:** Глобальный стандарт, поддерживающий все письменности мира, специальные символы и эмодзи.
- **Зачем нужен:** Решает проблему ограниченности ASCII.
- **Пример:** `U+1F600` → эмодзи 😀.

### 3. Кодировки Unicode
| Кодировка | Размер символа | Применение |
| :--- | :--- | :--- |
| **UTF-8** | 1–4 байта | Самая популярная, используется в вебе, совместима с ASCII. |
| **UTF-16** | 2–4 байта | Используется в Windows, Java, .NET. |
| **UTF-32** | 4 байта | Простая, но неэкономичная (много памяти). |

### 4. Связь с безопасностью (практическое применение)
| Концепция | Как используется в ИБ | Пример |
| :--- | :--- | :--- |
| **Понимание кодировок** | Анализ текстовых данных, логов, предотвращение ошибок. | Правильное чтение текста из разных источников. |
| **UTF-8** | Используется в веб-приложениях → важно для предотвращения XSS. | Экранирование ввода в UTF-8. |
| **Unicode** | Атаки на основе похожих символов (Unicode spoofing). | Использование `℀` вместо `@` для фишинга. |
| **UTF-16/UTF-32** | Анализ бинарных данных и дампов памяти. | Поиск строк в памяти. |
