# TryHackMe: HTTP in Detail

## 📌 Краткое описание
Пройден модуль, посвящённый протоколу HTTP — основе веб-коммуникации. Изучены структура URL, HTTP-методы, заголовки, статус-коды и механизм cookies. Понимание HTTP критично для анализа веб-трафика, выявления уязвимостей и защиты веб-приложений.

## 🛠️ Ключевые навыки, полученные в модуле

### 1. Понимание HTTP-протокола
- **URL:** Знаю структуру (схема, хост, путь, параметры, фрагмент).
- **HTTP-методы:** Понимаю разницу между GET, POST, PUT, DELETE и их применение.
- **Заголовки:** Знаю ключевые заголовки запроса (Host, User-Agent, Cookie, Referer) и ответа (Set-Cookie, Content-Type, Cache-Control).
- **Коды статуса:** Понимаю основные коды (200, 404, 403, 500, 301/302) и их значение.

### 2. Практическое применение в ИБ
- **Анализ запросов и ответов:** Могу анализировать HTTP-трафик для выявления аномалий и атак.
- **Понимание cookies:** Знаю, как работают cookies, как они используются для аутентификации и как их защищать (флаги HttpOnly, Secure, SameSite).
- **Безопасность заголовков:** Понимаю важность заголовков безопасности (Content-Security-Policy, Strict-Transport-Security).

### 3. Связь с реальными уязвимостями
- **XSS (Cross-Site Scripting):** Понимаю, как злоумышленники могут использовать cookies для кражи сессий.
- **CSRF (Cross-Site Request Forgery):** Знаю, как работает атака и как защищаться с помощью токенов.
- **Session Hijacking:** Понимаю, как перехват cookies может привести к угону сессии.

## 🧠 Примеры из практики
- Использовал инструменты разработчика (DevTools) для анализа HTTP-запросов и ответов.
- Изучал заголовки `Set-Cookie` и `Cookie` для понимания механизмов аутентификации.
- Анализировал статус-коды для диагностики веб-приложений.
